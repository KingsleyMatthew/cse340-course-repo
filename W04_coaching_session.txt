  * Configure Express middleware
  */

// Set up session management
app.use(session({
    secret: SESSION_SECRET,
    resave: false,
    saveUninitialized: true,
    cookie: { maxAge: 60 * 60 * 1000 } // Session expires after 1 hour of inactivity
}));

// Use flash message middleware
app.use(flash);


const flashMiddleware = (req, res, next) => {
    req.flash = function(type, message) {
        if (!req.session.flash) {
            req.session.flash = {
                success: [],
                error: [],
                warning: [],
                info: []
            };
        }

        if (type && message) {
            if (!req.session.flash[type]) {
                req.session.flash[type] = [];
            }
            req.session.flash[type].push(message);
            return;
        }

        if (type && !message) {
            const messages = req.session.flash[type] || [];
            req.session.flash[type] = [];
            return messages;
        }

        const allMessages = req.session.flash || {
            success: [],
            error: [],
            warning: [],
            info: []
        };

        req.session.flash = {
            success: [],
            error: [],
            warning: [],
            info: []
        };

        return allMessages;
    };

    next();
}

const flashLocals = (req, res, next) => {
    res.locals.flash = req.flash;
    next();
}

const flash = (req, res, next) => {
    flashMiddleware(req, res, () => {
        flashLocals(req, res, next);
    });
};

export default flash;

Good. You’ve shown both sides of the implementation: the session stores the flash data, while your custom middleware provides the `req.flash()` function for adding and retrieving messages.

One important detail is that your middleware is registered after `express-session`, so `req.flash()` has access to `req.session`.

In your own words, why are flash messages stored in the session instead of simply setting a normal variable like `let message = "Category added successfully!"`?

STUDENT:
Because of what happens between setting the message and displaying it: a redirect.

Look at the flow, `processNewCategoryForm` sets the flash message, then calls `res.redirect(...)`. A redirect isn't "keep running the same request and show different content", it tells the browser to make a brand new HTTP request to a different URL. That new request hits a completely different route handler, running fresh, with none of the local variables from the first request still around. A plain `let message = "..."` would exist for exactly as long as that one function call, then vanish the moment the response was sent, the next request wouldn't know it ever existed.

The session solves this because it's not tied to a single request, it's data that persists on the server between requests from the same browser, matched up via a cookie. So storing the message in `req.session.flash` means: request 1 writes it into storage that outlives the request itself, then request 2 (the page the user lands on after the redirect) can read it back out of that same storage.

That's also why the flash function clears the message after reading it, once it's been displayed, it's no longer needed sitting in the session waiting to reappear on the next page too.
